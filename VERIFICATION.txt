Storage fix, 2026-10-08 (Claude)
  Found in use: after adding a photo, the editor reported that browser
  storage was full, so recent changes were not saved. Cause: the saved
  Undo history had no budget and could crowd out the page's own autosave,
  and Add image stored photos at full size (history kept a second copy).
  studio.js: the page saves first; if storage is full, saved history is
    dropped and the page saved again. Saved history is kept under about
    1.5 million characters (fewer steps when needed).
  studio.js / sculpt.js: Add image scales photos to 1600 pixels like Replace
    image (ClayBridge.shrink); large PNGs are written as WebP, which keeps
    transparency. Raster files up to 25 MB are accepted; SVG and GIF up to
    4 MB, unchanged.
  Headless Waterfox 153, real input: 5/5. A 4 MB, 3000x2000 photo went in at
    1600x1067 (about 1 MB); 25 moves all saved with history inside its
    budget; with storage filled to the brim the next move still saved; after
    reopening the last move was there and Undo stepped back. Regression:
    split 6/6, revision 9/9, Sculpt 30/30, groups 8/8, Layout tools and
    classic 13/13, npm test 22/22.

Self-host: Docker and network access, 2026-10-09 (Claude)
  serve.py: listens on 127.0.0.1 unless asked (--host or CLAY_HOST); port
    from the argument, --port or CLAY_PORT; saved pages go to CLAY_DATA
    (--data), served back from there under /exports/. CLAY_PASSWORD (or
    CLAY_PASSWORD_FILE) asks for a password with HTTP Basic auth, any user
    name, compared in constant time. Export accepts only the editor opened
    from this server, under whatever address it was opened (Origin must
    match Host). A local server refuses requests addressed to any other name,
    so a website can't reach it by pointing its own name at 127.0.0.1.
    /healthz answers without a password and isn't logged. It stops cleanly
    on SIGTERM, which a container's first process otherwise ignores.
  Dockerfile (python:3.12-alpine, runs as uid 1000, /data volume, health
    check), compose.yaml (port 8920, password from .env, restart
    unless-stopped), .dockerignore (only runtime files go in the image).

Pages on the server, 2026-10-09 (Claude)
  serve.py: / opens the page list (pages.html). Each page lives in
    data/pages/<name>/: page.html (what it started from), state.json (its
    saved work and undo history, with a revision number) and meta.json
    (title, dates). /p/<name>/ opens a page with its saved work inside it
    (every < escaped), and the runtime beside it. API: list, new (Simple
    start, the Clay sample, or a copy of a page), rename (title only; the
    address stays), delete (to data/trash), restore, and save. A save from
    an older copy than the server's is refused (409) instead of overwriting.
    Pages and the trash are never served as files. Default data folder is
    now ./data (ignored by git and Docker builds); exports are in data/exports.
  studio.js: where work is kept is one small layer (shelf): the browser, as
    before, or, for a page opened from the list, the server: the saved work
    arrives with the page, changes go back 0.6s after the last one (only the
    parts that changed), retries back off to 30s when the server can't be
    reached, a refused save stops saving and says so, closing with unsaved
    work asks first, and what fits in a keepalive request goes on the way out.
  sculpt.js: ← Pages (saves first), and the status line says where work is
    saved. pages.html: the list, New page dialog, rename, duplicate, delete
    with Undo. starters/blank.html: Simple start.
  The classic Clay-Studio copy is unchanged: it has no page server, so
    server saving could never switch on there.
  qa/server.test.py: 38/38, adding 18 page checks (names, saving, the 409,
    partial saves keep the undo steps, saved text that looks like HTML stays

  Headless Waterfox, real input: 11/11. Empty list; New page → Simple start
